# 要件定義仕様書 — AI支援型アクティブリーディングツール

- 文書名: 要件定義仕様書
- 仮称: Active Reader Skill
- バージョン: v0.1
- 作成日: 2026-10-11
- ステータス: 初期要件整理版

---

## 1. 目的

本システムは、技術書・技術記事・論文などを読む際に発生する「前提知識が足りず理解できない」「読んだつもりになってしまう」「理解した内容を自分の言葉で説明できない」「復習すべき箇所が整理されない」といった問題を解消するための、AI支援型アクティブリーディング環境を提供する。

単なる電子書籍リーダーではなく、読書中の疑問・理解・自己説明・問題生成・復習を一連の学習フローとして扱い、読書記録を構造化データとして保存し、AIスキルから再利用可能にすることを目的とする。

---

## 2. 背景と課題

技術書では数学書のように使用する定義や前提が常に明示されるとは限らず、本文中に既知であることを前提とした用語や概念が突然登場することがある。そのため、読者は本文の主題とは別の箇所で理解が止まりやすい。

また、単純な再読だけでは「見覚えがあること」と「説明できること」を区別しにくい。そこで、本システムでは以下の学習行動を明示的に支援する。

1. 分からない箇所を読書中に記録する。
2. AIによって前提知識や概念説明を補う。
3. 読者自身が内容を自分の言葉で説明する。
4. AIが自己説明を評価し、誤りや不足を指摘する。
5. 重要箇所から確認問題を作る。
6. 後日、問題・自己説明・再読によって理解を確認する。

---

## 3. 対象ユーザー

主対象は、プログラミング、AI、クラウド、ネットワーク、数学、論文などの専門的な文章を読む学習者・エンジニアとする。

特に、文章自体は読み進められるが、途中に現れる前提知識や専門用語によって理解が途切れるユーザーを想定する。

---

## 4. システムの基本方針

### 4.1 Local-first

文書閲覧、アノテーション、メモ、JSON保存などの基本機能はローカル環境で動作することを基本とする。

### 4.2 CLI + Web UI

Pythonパッケージとして提供し、`uv` でインストール・実行可能とする。CLIからローカルサーバーを起動し、ブラウザ上のHTMLインターフェースで文章を読む構成とする。

### 4.3 AI機能の分離

文書閲覧機能とAI処理を密結合させず、読書記録をJSON等の中間形式に保存し、AIスキル側はその構造化データを入力として処理する。

### 4.4 拡張可能性

初期対応をMarkdown中心とし、将来的にPDF、HTML、EPUB、テキスト、Web記事などへ拡張可能な構造とする。

## 5. 想定利用フロー

### Phase A: 読む

ユーザーはCLIから対象文書を開き、ブラウザのReader画面で本文を読む。

### Phase B: 分からない箇所を記録する

本文中の文字列を選択し、「分からない」として紫色のマーカーを付与する。必要に応じて右側のパネルに「何が分からないのか」「どこが気になるのか」を自由記述する。

### Phase C: AIに説明させる

読了後または任意のタイミングで、紫色マーカーをまとめてAI処理へ渡す。AIは本文の前後文脈、ユーザーのメモ、対象箇所を参照し、概念説明・前提知識・必要に応じた図式的説明を生成する。

### Phase D: 自分の言葉で説明する

理解したと思った箇所を別種のマーカーで指定し、右側パネルに自分自身の説明を書く。

### Phase E: AIによる理解評価

AIがユーザーの自己説明と原文・関連資料を比較し、正しい点、不足している点、誤解している点をフィードバックする。

### Phase F: 問題を作る

「ここは問題にしたい」と指定した箇所を別種のマーカーとして保存する。AIはその情報から確認問題を生成する。

### Phase G: 復習する

後日、生成された問題や自己説明課題を提示し、回答後にフィードバックする。必要に応じて原文へ戻り、該当箇所を再読する。

## 6. 機能要件

### FR-01 文書読み込み

システムはローカルファイルを読み込めること。

初期必須形式:

- Markdown (`.md`)
- Plain Text (`.txt`) ※実装負荷が低いため同時対応を推奨

将来対応候補:

- PDF
- HTML
- EPUB

### FR-02 Reader表示

読み込んだ文書をブラウザ上で可読性の高い形式で表示すること。

Reader画面では最低限、以下を提供する。

- 本文表示
- 見出し構造の保持
- スクロール位置保持
- テキスト選択
- マーカー表示
- 右側サイドパネル

### FR-03 テキスト選択

マウスまたはトラックパッドで本文の任意範囲を選択できること。

選択した文章について、アノテーション種別を指定できること。

### FR-04 アノテーション種別

初期版では最低限3種類を扱う。

| 種別 | 仮カラー | 意味 |
|---|---|---|
| Unknown | 紫 | 分からない・前提知識が不足している |
| Explain | 青 | 自分の言葉で説明して理解を確認したい |
| Quiz | 要決定 | 後で問題として出題してほしい |

色そのものは設定可能にすることが望ましい。

### FR-05 アノテーション操作方法

本文選択後、以下のいずれかまたは両方で種別を指定できること。

- キーボード修飾キー + 選択
- 選択後に表示されるフローティングツールバー

ショートカットは設定変更可能とすることが望ましい。

### FR-06 メモ入力

アノテーション作成時、右側サイドパネルに自由記述のメモ欄を表示すること。

Unknownの場合は「何が分からないか」、Explainの場合は「自分の理解」、Quizの場合は「どの観点から問いたいか」を記述可能とする。

### FR-07 永続化

文書に対する読書記録を構造化データとして保存すること。

保存対象には最低限以下を含む。

- 文書ID
- 文書パス
- 文書ハッシュ
- アノテーションID
- 選択文字列
- 選択範囲の位置情報
- 前後文脈
- アノテーション種別
- ユーザーメモ
- 作成日時
- 更新日時
- AI処理結果
- 学習ステータス

### FR-08 JSONエクスポート

読書記録をJSONとして出力できること。

AIスキルや外部ツールから処理しやすい安定したスキーマを定義する。

### FR-09 Unknown説明生成

UnknownアノテーションをAIへ渡し、説明を生成できること。

AIには最低限以下を渡す。

- 選択文字列
- 前後文脈
- ユーザーメモ
- 文書タイトル・見出し

生成結果には最低限以下を含む。

- 簡潔な説明
- 必要となる前提知識
- 本文における意味
- 必要に応じた例
- 関連概念

### FR-10 自己説明入力

Explainアノテーションについて、ユーザーが自分の理解を文章として入力できること。

AIによる説明を先に表示せず、ユーザー自身の想起・言語化を先に行えるモードを用意する。

### FR-11 自己説明評価

ユーザーの自己説明をAIが評価できること。

評価結果は単純な正誤だけではなく、最低限以下に分ける。

- 正しく説明できている内容
- 不足している内容
- 誤っている内容
- 曖昧な内容
- 改善された説明例

数値スコアを付与する場合は、スコア根拠も保持する。

### FR-12 外部検索

自己説明の検証やUnknown説明に必要な場合、AIスキルが外部情報を検索可能とする。

検索結果を利用した場合は、可能な限り出典を保持する。

※外部検索の標準ON/OFFは未決定事項とする。

### FR-13 問題生成

Quizアノテーションから確認問題を生成できること。

問題形式は将来的に複数対応できる設計とし、初期版では以下を候補とする。

- 自由記述
- 用語説明
- Why/How型の概念理解問題
- 穴埋め
- 選択問題

技術書の理解確認では自由記述を優先する。

### FR-14 問題回答

生成問題に対してユーザーが回答を入力できること。

回答後、AIが採点・フィードバックし、元の該当箇所へ移動できること。

### FR-15 復習状態管理

各アノテーション・問題について理解状態を保持する。

状態例:

- new
- learning
- understood
- review_required
- mastered

初期版では厳密な間隔反復アルゴリズムを実装せず、手動または単純な復習日管理でもよい。

### FR-16 読書セッション

1回の読書開始から終了までをSessionとして記録可能とする。

将来的に以下の分析へ利用できるようにする。

- 読書時間
- 章ごとの滞在時間
- Unknown数
- 自己説明数
- 問題数
- 理解状態の変化

### FR-17 原文ジャンプ

アノテーション、AI説明、問題、復習画面から元文書の該当箇所へ戻れること。

### FR-18 検索

アノテーションおよびメモを全文検索できることが望ましい。

## 7. CLI要件

Pythonパッケージとして提供し、`uv` ベースで利用できること。

仮コマンド例:

```bash
uvx active-reader open book.md
uvx active-reader serve
uvx active-reader export book.md --format json
uvx active-reader explain --document book.md
uvx active-reader quiz --document book.md
uvx active-reader review
```

CLIコマンド名は正式名称決定後に変更可能とする。

### CLIの責務

CLIは以下を担当する。

- Web UI起動
- 文書指定
- データ保存先指定
- JSONエクスポート
- AIスキル呼び出し
- 設定表示・変更

## 10. AI Skill要件

AIスキルはUIそのものに依存せず、JSONデータを入力として処理できること。

概念上、以下の操作を独立した機能として扱う。

```text
explain(annotation)
evaluate(annotation, user_explanation)
generate_quiz(annotation)
grade(question, user_answer)
review(document/session)
```

### Skill入力

- 文書情報
- アノテーション
- 周辺コンテキスト
- ユーザーメモ
- 過去のAI処理結果
- 必要に応じてユーザー回答

### Skill出力

機械可読JSONと、人間向けMarkdownの両方を扱える設計が望ましい。

## 11. AIの振る舞い要件

AIは「正解をすぐ教える」だけではなく、学習を阻害しないようモードを分ける。

### Explain Mode

知らない概念を理解するための説明を行う。

### Recall Mode

原文・AI説明を隠した状態で、ユーザー自身に説明させる。

### Evaluate Mode

ユーザー回答を評価する。

### Quiz Mode

理解確認問題を作成する。

### Review Mode

過去の間違い・理解不足を優先して再出題する。

## 13. 保存方式

初期MVPではJSONファイルで実装可能とする。

ただし、複数文書・大量アノテーション・検索・履歴管理を考慮すると、内部保存にSQLiteを使用し、外部連携用にJSONエクスポートする方式を推奨する。

推奨構成:

```text
.active-reader/
├── config.json
├── active_reader.db
├── exports/
│   └── document_xxx.json
└── cache/
```

## 14. 非機能要件

### NFR-01 起動性

1コマンドでWeb UIを起動できること。

### NFR-02 クロスプラットフォーム

最低限以下を対象とする。

- macOS
- Windows
- Linux

### NFR-03 データ保護

ユーザー文書・メモをユーザーの明示操作なしに外部送信しないこと。

AI処理時に外部LLMへ送信するデータ範囲を設定可能とすることが望ましい。

### NFR-04 再現性

同一文書を再度開いた際に、可能な限り同じ位置にアノテーションを復元する。

単一の文字offsetだけでなく、選択テキスト、前後文脈、見出し等を併用して復元可能とする。

### NFR-05 可搬性

読書記録をJSONとして持ち出せること。

### NFR-06 AIベンダー非依存

OpenAI等の特定ベンダーにロジックを密結合しない。

AI Adapter層を設けることを推奨する。

### NFR-07 応答性

マーカー付与やメモ入力など、AIを使用しない操作はローカルで即時反映されること。

## 16. MVP受け入れ条件

以下が一連で成立した時点を最初の完成基準とする。

1. `uv` 経由でアプリを起動できる。
2. Markdownファイルを指定してブラウザで開ける。
3. 任意テキストを選択して紫色のUnknownマーカーを付けられる。
4. メモを書いて保存できる。
5. アプリを閉じても、再度開くとマーカーが復元される。
6. UnknownをAIへ送って説明を取得できる。
7. Explainとして自分の説明を書ける。
8. AIが自己説明を評価できる。
9. Quiz指定した箇所から問題を作れる。
10. すべての読書記録をJSONとして出力できる。

## 18. 現時点での未決定事項

以下は実装前に仕様決定が必要。

### Q1. 初期リリースでPDFを含めるか

案A: MarkdownのみでMVPを早く完成させる。

案B: 技術書用途を重視し、最初からPDF.jsを入れる。

推奨: A。

### Q2. Quizマーカーの色

紫=Unknown、青=Explainまでは会話で決定しているが、Quiz色は未決定。

候補: 緑またはオレンジ。

### Q3. AIによる外部検索

自己説明評価を原文のみで行うのか、Web検索や論文検索も利用するのか。

推奨: 通常は原文優先。ユーザーが「外部検証」を指定した場合のみ検索。

### Q4. AIプロバイダー

OpenAI固定か、複数Provider対応か。

推奨: Provider Adapter方式。

### Q5. データ保存

JSONを正本にするか、SQLiteを正本にしてJSONをexport形式とするか。

推奨: SQLiteを正本、JSONをAI Skillとの交換形式。

### Q6. 復習アルゴリズム

単純な「未理解だけ表示」から始めるか、FSRS等の間隔反復を最初から導入するか。

推奨: MVPでは単純方式。

### Q7. AI Skillの実行形態

候補:

- CLIから呼ぶ
- Python APIとして呼ぶ
- MCP Toolとして公開する
- ChatGPT/Codex等のSkillとして利用する

これらを同一Core API上に載せるかを決定する必要がある。

> 読む → 分からない箇所を残す → AIで理解する → 自分の言葉で説明する → AIに評価してもらう → 問題として思い出す → 必要な箇所だけ読み直す

本システムの中心は「AIに説明させること」ではなく、読者自身による理解・想起・説明をAIで支援することである。
